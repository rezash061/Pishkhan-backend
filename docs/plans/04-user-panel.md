# User Panel Implementation Plan (Next.js, PWA)

**Read first:** `00-overview.md` (assumptions, API conventions, realtime events, shared frontend foundation in section 10, phase map).
**App:** `frontend/apps/panel` plus ownership of the shared packages in `frontend/packages/*` (work package UP-0.1).
**Users:** Instagram sellers and creators (often running the shop from a phone), their team members (agents answering DMs), and agencies managing many pages (Phase 3).
**Backend:** `Api` host `/api/v1/*`, SignalR hub `/hubs/inbox`, OpenAPI `backend/openapi/api.v1.json` (backend plan section 9).

---

## 1. Purpose and principles

This is the product. A seller signs up, connects Instagram, has a useful AI sales agent in minutes, then lives in the inbox and orders screens.

1. **Mobile first.** Most sellers manage everything from a phone (report section 3). Design every screen at 360 px first; desktop gets more columns, not different features. Installable PWA; Android packaging for Cafe Bazaar and Myket through a Trusted Web Activity (Phase 2).
2. **Minutes to value.** Onboarding must reach a working bot fast: official Instagram connect, industry template, conversational onboarding, feed import (Phase 2), test mode, knowledge score (report features 21–24, gap G20).
3. **Trust the AI by seeing it.** Show why the AI said something: sources used, confidence, tool actions, and one-tap "add to knowledge" (gap G28).
4. **Never silent.** Clear banners for channel disconnection, Instagram outages, quota and overage, and AV-rejected files.
5. **Persian, RTL, Jalali, Toman** everywhere, with Finglish/Persian/Arabic digit-tolerant inputs.
6. **Works on bad networks.** Small bundles, optimistic UI with retry, resilient realtime reconnection, offline-tolerant queue in Phase 4 (G13).

### 2.2 Authentication and session

- Phone OTP: `PhoneInput` accepts `09...`, `+989...`, Persian or Arabic digits; ALTCHA solved in the background before `otp/request`; 60-second resend countdown; OTP input with `autocomplete="one-time-code"` (Android SMS autofill).
- Tokens in `__Host-` cookies via BFF (overview section 5). Refresh is single-flight across tabs (BroadcastChannel lock).
- TOTP challenge when enabled; prompt Owners to enable TOTP before connecting payment settings.
- Sessions page lists devices and allows revoke.
- **Support sessions (impersonation):** `/api/auth/impersonation?token=` exchanges a one-time token; the shell shows a persistent red banner «نشست پشتیبانی — کارشناس X» with an end button; billing and payment-credential screens are read-only in this mode.

### 2.3 Permissions

`can(permission)` from the workspace membership (`workspace.inbox.reply`, `workspace.automation.write`, `workspace.catalog.write`, `workspace.orders.manage`, `workspace.billing.manage`, `workspace.team.manage`, `workspace.settings.manage`...). Nav items and actions hidden when not permitted; direct URL shows a Persian 403 page. Roles: Owner, Admin, Agent, Viewer (custom roles in Phase 3).

### 2.4 Global UX patterns

- **Banners** (top of workspace layout, from workspace status + SignalR `channel.status` + announcements): Instagram disconnected/reauth required (with reconnect button), token expiring, Instagram outage declared (with "move my customers" CTA, Phase 2), quota 80%/100%/overage cap, support session, admin announcements.
- **Plan limits:** a `402 plan-limit` response opens an upgrade sheet naming the limit.
- **File uploads:** `FileUpload` shows upload → «در حال بررسی امنیتی» → ready, or «فایل به دلایل امنیتی رد شد» (infected/rejected), polling file status or listening to a notification.
- **Empty states** that teach (each with a one-line explanation and a primary action).
- **Keyboard shortcuts** on desktop inbox (`j/k` navigate, `r` reply, `e` close, `a` assign).
- **Numbers:** Persian digits in display; inputs accept any digits; money inputs in Toman with live thousands separators.

## 3. Feature specifications

### 3.1 Onboarding (Phase 1; template and import in Phase 2)
1. **Workspace:** business name, industry (the five launch verticals + other), city, timezone default Asia/Tehran.
2. **Connect Instagram:** explain official connection and that no password is ever requested; button starts OAuth (`POST /channels/instagram/connect` → redirect); callback returns to `/onboarding/connect?status=`; handle errors in Persian (not a professional account, permissions declined) with a help link explaining how to switch to a Professional account.
3. **Template** (Phase 2): pick an industry template; preview what it adds (FAQs, flows, rules, agent tone).
4. **Import** (Phase 2): run feed import; review extracted products, prices and FAQs as editable draft cards (accept, edit, reject, accept all); nothing goes live until confirmed.
5. **Teach:** conversational onboarding chat; the assistant asks about products, prices, shipping, payment methods, returns, hours; each extracted fact appears as a confirm/edit card before saving; knowledge score meter updates live.
6. **Test:** test-mode chat (Sandbox channel) where the owner role-plays a customer; side panel shows sources used, tools called, confidence; "this answer is wrong" → correct it → saved to knowledge. "Go live" toggles AI on for the Instagram account with a recommended confidence threshold.
- ✅ A new user can go from sign-up to "AI live" in under 10 minutes in a usability test; every step is resumable (state from backend), and skipping is allowed except Instagram connect for going live.

### 3.2 Dashboard
- Overnight summary card ("۴۷ دایرکت پاسخ داده شد، ۹ خرید" style, from backend), KPIs (conversations, answered by AI / rules / humans, handoffs waiting, leads captured, orders and revenue from Phase 2), knowledge score with top missing items, unanswered questions count, channel health, quota usage.
- ✅ First paint from server component; numbers are links to filtered inbox/contacts/orders.

### 3.3 Inbox (the most important screen)
- **Layout:** desktop three panes (conversation list, thread, contact/context side panel); mobile list → thread → side sheet.
- **List:** filters (all, mine, unassigned, handed off/waiting, AI handling, closed; channel; tag), search (contact name/username/phone), unread badges, last message preview with direction icon, SLA timer on handed-off conversations, infinite scroll (cursor).
- **Thread:** messages grouped by day with Jalali date separators; bubbles for text, image, video, audio (voice notes with player and **transcript** in Phase 2), story replies (story preview), post shares, cards/carousels, system events (AI handed off, assigned, order created); label on each outbound message showing who sent it (rule name, AI, team member); AI messages have an expandable "why" (sources, confidence, tools); Finglish messages show the transliterated Persian beneath (Phase 2).
- **Composer:** text with emoji, quick replies (`/` to search), attachments (AV pipeline), product card picker from catalog, payment link button (Phase 2), AI suggested reply (when handed off with a suggestion) with "use/edit"; **24-hour window indicator** with countdown; when the window is closed, composer explains it and only allows a human-agent reply within 7 days; sending is optimistic with retry on failure and per-message status (sent, delivered, read, failed with reason).
- **Actions:** assign (self/teammate), close/reopen, pause/resume AI for this conversation, add note (internal, mentions), add tags, create order (Phase 2), mark receipt (Phase 2).
- **Side panel:** contact profile (name, username, phone with consent status, tags, custom fields, lead score in Phase 4), previous orders, form submissions, notes, conversation source post (attribution, Phase 3).
- **Realtime:** `message.created`, `conversation.updated`, `message.status`, `handoff.requested` update caches; reconnect with backoff and refetch on resume; a sound/vibration option for new handoffs; web push when the app is in background (with in-app fallback because push may be unreliable in Iran).
- ✅ New inbound message appears in < 1 s on two devices; composer blocks standard replies when the window is closed; 5,000 conversations list scrolls smoothly on a mid-range Android (virtualized list).

### 3.4 Automations
- **Rules list** per Instagram account, grouped by trigger type, with enable toggles, priority drag-and-drop, stats (fired, conversions).
- **Rule editor** (form-based, simple cases): trigger (DM keyword, comment keyword with post picker from account media incl. "next post", all comments on a post, story reply, story mention, live comment, post share, welcome, outside business hours), keywords input with match type and Persian-normalized preview ("also matches: قيمت، قیمت"), action (message builder with variables, private reply, public reply variants, start flow, tag, handoff, follow-up).
- **Comment-to-DM wizard:** pick post → keyword → DM content → public reply variants → optional follow-gate → done; includes "reply to existing comments" (backlog) with a progress indicator.
- **Flow builder:** canvas with node palette (message, question, condition, delay, follow-gate, storefront, action, AI, end), node inspector side panel, validation errors highlighted (server validation via `/flows/{id}/validate`), auto-layout, zoom/pan, mobile view as a read-only vertical list with edit sheets (canvas editing is desktop-first), versioning (draft/published), test run in sandbox.
- **Message builder** (shared by rules, flows, broadcasts): text with variables, media, voice, buttons (URL, postback), quick replies, carousel cards from storefront; live preview in an Instagram-like DM mock (RTL).
- **Follow-ups:** list of scheduled follow-ups and templates (for example "discount one day after product link"), with explanation of the 24-hour window.
- ✅ Builders produce JSON accepted by the backend validator; Persian-keyword preview matches backend normalization (shared test cases from backend `Pishkhan.Persian.Tests` exported as JSON fixtures).

### 3.5 AI agent
- **Settings:** bot name, tone (friendly/formal/playful) with example replies, brand voice description, languages (reply in customer's language), "answer only from my information" (locked on by default), never-say list, confidence threshold slider with plain explanation, handoff triggers (human request, complaint, discount request, keywords, VIP tag), working hours behavior, negotiation guardrails (Phase 3: minimum prices, discount ladders).
- **Test:** same test-mode chat as onboarding, available anytime.
- **Traces:** list of recent AI replies with confidence and outcome (resolved, handed off, customer bought), filters for low confidence; detail shows sources and tool calls.
- ✅ Changing a setting is reflected in test mode immediately (cache invalidated by backend).

### 3.6 Knowledge
- Sources list (FAQ, documents, URLs, catalog, onboarding, feed) with status (indexing, ready, failed), add FAQ (question variants + answer), upload document (AV pipeline), add URL.
- **Unanswered questions** inbox: questions the AI could not answer, grouped by similarity, with "answer once" → saved as FAQ.
- **Knowledge score** page: score, missing required facts per industry template, suggestions.
- ✅ Answering an unanswered question makes the test-mode bot answer it correctly within 1 minute.

### 3.7 Catalog and storefront
- Products list (search, category/tag filters, stock badges), product editor (title, description, images via AV pipeline, category, tags, variants matrix for size/color with price and stock, pricing mode; formula pricing in Phase 3), Excel import/export.
- Storefront cards: build carousels from products with button actions (order, more photos, pay, ask a question), preview in DM mock.
- **Bulk price update** (Phase 2, G8): select by category/tag/manual selection, percentage or fixed change, rounding rule, preview table (old → new), apply, undo within 24 h; banner confirms bot answers and cards are updated.
- **Gold/currency pricing** (Phase 3, G9): formula editor (weight × rate + making fee + profit), current rate display with source and time, preview price.

### 3.8 Orders and payments (Phase 2)
- Orders list (status tabs, search by number/contact, Jalali date range), order detail (items, totals, address, payment status, timeline, conversation link), manual create/edit, status changes (with automatic customer message toggles), printable invoice (Jalali, Persian digits).
- **Receipts queue** (G1): cards with the receipt image (clean file), extracted fields (amount, date, reference number, destination card), match result vs order with check marks (amount, destination card, time window, duplicate check), confidence; actions approve/reject with reason; filters; auto-approve setting with threshold (only after explaining risks).
- **Payment settings:** connect Zarinpal merchant ID (Owner, TOTP required), register bank cards/Sheba for receipt matching (validated client-side with Luhn/mod-97 before submit), payment link defaults (expiry).
- **Shipping** (Phase 3, G4): enter tracking code → automatic customer message; carrier selection; shipping costs by city; shipment status.

### 3.9 Contacts and CRM
- Contacts table (virtualized, server-side filters: tags, segment, channel, has phone consent, last seen), contact detail, tags management, segments builder (conditions UI → rule JSON), forms (list forms used in flows, submissions table), Excel export (async with notification and download).

### 3.10 Channels and outage resilience
- Instagram accounts: connection status, permissions, reconnect, disconnect, rate/viral mode status, last webhook received.
- **Phase 2 (G11):** SMS sender setup (provided by platform, billed per SMS), Bale bot connection (guided steps), phone capture settings (when and how the bot asks for phone consent), **outage center**: shows Instagram reachability, consented contacts count by channel, "move my customers" campaign builder (message + channels + segment), and its delivery report.
- Phase 3: Rubika, Eitaa, Telegram, web widget (embed code generator).

### 3.11 Team
- Members list, invite by phone (SMS link), roles, remove; seat usage vs plan; Phase 3 custom roles.

### 3.12 Billing
- Current plan, usage meters with progress bars (AI conversations etc.), overage this period and cap setting (Phase 2), upgrade/downgrade with proration preview, checkout via Zarinpal (redirect and return page with verification result), wallet balance and top-up, invoices list and PDF download, annual plan installments (Phase 2), coupon entry.

### 3.13 Settings
- General (name, logo, industry), business hours (weekly schedule + Jalali holidays with presets for Nowruz etc.), notifications preferences, payments (3.8), developers (Phase 3: API keys shown once, webhooks with secret and delivery logs), danger zone (delete workspace with typed confirmation and 30-day grace).

### 3.14 Phase 3 features
- **Analytics:** attribution (post/Reel/story/live → conversations → orders → revenue) with media thumbnails (G23); weekly Persian insights page (top questions, lost-sale reasons, demand trends) (G24).
- **Content studio** (G19): caption, hashtag and Reels script generator using the catalog and brand voice, with copy buttons; Persian typography preview.
- **Campaign generator and Jalali planner** (G21, G22): calendar of Iranian occasions; "create Yalda giveaway" wizard producing caption + keyword rule + flow + follow-up in one step.
- **Moderation** (G25): settings for auto-hide categories, moderated comments log with undo.
- **Agency mode** (G29): organization switcher, client workspaces grid with health and usage, white-label settings (logo, colors, custom subdomain), client billing view.

## 6. Performance budget

| Route | Budget |
|---|---|
| Login / OTP | JS < 90 KB gz, LCP < 1.8 s on slow 4G |
| Dashboard | LCP < 2.5 s |
| Inbox | JS < 250 KB gz (flow builder, charts, editors lazy-loaded elsewhere); list virtualized; thread messages paginated |
| Flow builder | Lazy-loaded route chunk; canvas usable with 200 nodes at 60 fps on desktop |

Techniques: server components for initial lists, `dynamic()` imports for heavy editors, image thumbnails from backend derivatives, TanStack Query `staleTime` tuned per resource, prefetch on hover/focus on desktop only, avoid layout shift with skeletons.
